## 1. Unit overview

`m_demo_mapping3` is a member/subscriber validation mapping with hard ABORT guards and a
router split, read directly from the PowerCenter export:

- **Source**: `demo_source2` (Oracle, owner `APIUSER`) — member records with 14 columns:
  `Title`, `First_Name`, `Middle_Name`, `Last_Name`, `Member_ID`, `Member_Suffix`,
  `Birth_Date`, `Gender_Code`, `Member_Record_Number`, `Social_Security_Number`,
  `Member_Type_Code`, `Original_Effective_Date`, `Relationship_to_Subscriber_Code`,
  `Relationship_to_Subscriber_Code_Label`.
- **Pipeline** (4 instances): `demo_source2` → `SQ_demo_source2` (Source Qualifier) →
  `EXPTRANS` (Expression) → `RTRTRANS` (Router) → two target instances.
  - `SQ_demo_source2` carries a **SQL override**:
    `SELECT ... FROM demo_source2 WHERE demo_source2.Member_Type_Code IS NOT NULL` —
    rows with a NULL member type never enter the pipeline.
  - `EXPTRANS` is a pass-through for 14 ports plus one guarded output port:
    `o_Relationship_to_Subscriber_Code_Label =
    IIF(ISNULL(Relationship_to_Subscriber_Code_Label),
        ABORT('Relationship_to_Subscriber_Code_Labe valuel is null'),
        Relationship_to_Subscriber_Code_Label)`
    (port default value `ERROR('transformation error')`). A NULL label on any
    filtered-in row **aborts the whole session**.
  - `RTRTRANS` splits on Social Security Number:
    | Group | Condition | Routed to |
    |---|---|---|
    | `NEWGROUP1` | `ISNULL(Social_Security_Number)` | instance `demo_target2` |
    | `NEWGROUP2` | `NOT ISNULL(Social_Security_Number)` | instance `demo_target21` |
    | `DEFAULT1` | default group | **unconnected** (rows dropped) |
- **Targets**: both instances (`demo_target2`, `demo_target21`) write to the same target
  *definition* `demo_target2` (Oracle): `Title`, `Gender`, `First_Name`, `Middle_Name`,
  `Last_Name`, `Member_Identifier` (PRIMARY KEY, NOT NULL), `Member_Suffix`,
  `Date_of_Birth`, `Member_Number`, `Soc_Number`, `Type_Code`,
  `Relationship_to_Subscriber_Code`, `Relationship_to_Subscriber_Code_Label`,
  `Effective_Date`. Port renames along the way: `Member_ID → Member_Identifier`,
  `Birth_Date → Date_of_Birth`, `Gender_Code → Gender`,
  `Member_Record_Number → Member_Number`, `Social_Security_Number → Soc_Number`,
  `Member_Type_Code → Type_Code`, `Original_Effective_Date → Effective_Date`.
  For the `NEWGROUP1` branch `Soc_Number` is NULL by construction.

dbt implementation of this unit (unchanged by this packet):
`models/staging/stg_demo_source2.sql` → `models/intermediate/int_m3_filtered.sql`
(SQL-override filter + ABORT guard expressed as a `not_null` schema test on
`o_relationship_to_subscriber_code_label`) → `models/marts/demo_target2.sql` /
`models/marts/demo_target21.sql` (router groups as `WHERE` predicates).

## 4. Snowflake notes

Items in this unit's SQL a Snowflake deployment should review:

- **ABORT guard has no direct Snowflake equivalent.** The legacy
  `IIF(ISNULL(label), ABORT('...'), label)` halts the whole session on bad data. The dbt
  port models it as a `not_null` test on `int_m3_filtered.o_relationship_to_subscriber_code_label`;
  on Snowflake, keep that test with `severity: error` (build fails, mimicking the abort)
  or enforce it in-query with a division-by-zero/`ERROR` UDF pattern if a hard runtime
  stop is required rather than a test-time failure.
- **Quoted mixed-case identifiers.** The mart models emit quoted mixed-case columns
  (`"Member_Identifier"`, `"Soc_Number"`, ...) to match the legacy target definition.
  Snowflake treats quoted identifiers as case-sensitive; either keep quoting everywhere
  (including downstream consumers and the parity keys) or standardize to unquoted
  upper-case and adjust `tools/keys/informatica_keys.json` accordingly.
- **Same-table dual loads.** Both router branches load the same physical table
  `demo_target2` in the legacy system (two target instances, `TARGETLOADORDER` both 1).
  The dbt port materializes them as two separate tables (`demo_target2`, `demo_target21`).
  A Snowflake deployment must decide: keep two tables, or `UNION ALL` into one table to
  match the original physical layout (then `Soc_Number IS NULL` distinguishes the branches).
- **SQL override belongs in the model, not the connection.** The Source Qualifier's
  `WHERE Member_Type_Code IS NOT NULL` is implemented in `int_m3_filtered`; no Snowflake
  session/connection-level filtering is needed.
- **Datatype mapping.** Legacy Oracle types: `number(15,0)` identifiers → Snowflake
  `NUMBER(15,0)`; `date` ports carried as date/time precision 29 scale 9 in PowerCenter →
  `DATE` (values are date-only in the seed data); `varchar2(n)` → `VARCHAR(n)`. `Soc_Number`
  is numeric in the legacy target — leading-zero SSNs cannot be represented; flag for the
  business before considering a change to `VARCHAR`.
- **Router default group is unconnected** — no rows can reach it because the two group
  conditions are exhaustive; nothing extra to implement, but do not add a catch-all branch.
- The unit is deterministic and non-incremental (full reload each run); simple table
  materializations are sufficient on Snowflake, no `MERGE`/update strategy needed.
