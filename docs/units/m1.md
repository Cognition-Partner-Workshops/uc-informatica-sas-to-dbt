# Unit Packet: `m_demo_mapping1`

Per-unit verification packet for the Informatica → dbt migration track.
Legacy artifact: `legacy/informatica/wf_demo_mapping.XML` (PowerCenter export, folder `RTUS`, mapping `m_demo_mapping1`).

## 1. Unit Overview

`m_demo_mapping1` ("Data Load for customer Detail and Credit Card summary table in DDS layer") is a
3-source mapping that joins account and transaction data, enriches it with three lookups, aggregates
transaction amounts, and routes rows to three targets by account type. A parallel, independent
pipeline in the same mapping loads a product flat file to a third target.

**Sources**

| Source | Type | Key columns |
|---|---|---|
| `demo_source3` | Oracle relational (transactions) | TX_ID, ACCT_ID, LAST_NM, TX_DTTM, TX_AMT, BAL_AMT, CUST_ID |
| `demo_source4` | Oracle relational (accounts) | ACCT_ID, ACCT_TYP, ACCT_DESC, CRDT_LN, CR8_DT, CLSR_DT, ACCT_STAT_CD |
| `demo_source5` | Comma-delimited flat file (products) | PRODUCT_ID, PRODUCT_NM, PRODUCT_NO, COLOR, STD_COST, LIST_PRICE, SELL_ST_DT, SELL_ED_DT |

Lookup tables (via Lookup Procedure transformations): `lkp_demo_source1` (FIRST_NM by ACCT_ID),
`lkp_demo_source2` (CRDT_SCORE by CUST_ID), `lkp_demo_source3` (used by `:LKP.lkp_TRANS1(ACCT_ID)`).
All three use "Use Last Value" on multiple match.

**Flow (from the XML)**

1. `sq_demo_source4` Source Qualifier has a SQL override that INNER JOINs `demo_source3` to
   `demo_source4` on `ACCT_ID`, selects `SYSTIMESTAMP` into the CR8_DT port, and orders by
   `ACCT_ID`.
2. `exp_TRANS` applies `RTRIM(ACCT_TYP)`, `LTRIM(CRDT_LN)` and the lookup expression
   `:LKP.lkp_TRANS1(ACCT_ID)`; `exp_TRANS1` applies `RTRIM(ACCT_DESC)` and carries the
   `lkp_TRANS2`/`lkp_TRANS3` lookup results (FIRST_NM, CRDT_SCORE).
3. `rtr_TRANS` Router: group `demo_target6_GRP` (`ACCT_TYP = 'SB'`), group `demo_target5_GRP`
   (`ACCT_TYP != 'SB'`), unconnected `DEFAULT1`.
4. `agg_TRANS` Aggregator (on the `demo_target6` path) computes `SUM(TX_AMT)` per ACCT_ID; all
   other ports are pass-through (PowerCenter last-row-per-group semantics).
5. `SEQ_GEN` Sequence (start 1, increment 1, current value 281, cycle YES) supplies
   `demo_target6.ACCT_KEY`.
6. Independent path: `SQ_demo_source5` → `exp_TRANS2` (date conversions on SELL_ST_DT/SELL_ED_DT)
   → `demo_target3`.

**Targets**

| Target instance | Fed by | Content |
|---|---|---|
| `demo_target3` | flat-file path | product reference rows (pass-through + date conversion) |
| `demo_target5` | router group `ACCT_TYP != 'SB'` | non-savings account transactions enriched with FIRST_NM and CRDT_SCORE lookups |
| `demo_target6` | router group `ACCT_TYP = 'SB'` + aggregator + sequence | per-account savings summary with SUM(TX_AMT) and generated ACCT_KEY |

### Notes (faithful anomalies, not fixed)

- sq_demo_source4 SQL override selects SYSTIMESTAMP into the CR8_DT port, discarding demo_source4.CR8_DT. Pinned to 2024-01-31 in the migration.
- sq_demo_source4 selects STRCMP(ACCT_STAT_CD, TX_TYPE_CD) into the TX_TYPE_CD port but that port is never connected downstream — a no-op.
- exp_TRANS2.o_SELL_ST_DT = TO_DATE(TO_CHAR(SYSDATE),'DD/MM/YYYY') is self-inconsistent: TO_CHAR(SYSDATE) renders MM/DD/YYYY HH24:MI:SS, which cannot be parsed with format DD/MM/YYYY (month 31 is invalid on the run date 2024-01-31). The port yields NULL for every row.
- The aggregator agg_TRANS only aggregates SUM(TX_AMT); all other ports are pass-through, which in PowerCenter returns the LAST row per ACCT_ID group. Determinism is defined as last-by-TX_ID within each ACCT_ID.
- Router group DEFAULT1 is not connected to any target: rows with NULL ACCT_TYP satisfy neither condition and are dropped.

## 4. Snowflake Notes

Items in this unit's SQL that a Snowflake deployment should review:

- **`SYSTIMESTAMP` / `SYSDATE` pinning** — the SQL override and `exp_TRANS2` reference the run
  date, pinned to `2024-01-31` in the dbt models. On Snowflake, replace the pinned literal with
  `CURRENT_TIMESTAMP` / `CURRENT_DATE` (or a run-date variable) as appropriate; note Snowflake's
  `CURRENT_TIMESTAMP` returns TIMESTAMP_LTZ — cast explicitly if the target column is TIMESTAMP_NTZ.
- **`STRCMP`** — the source-qualifier override calls Oracle-style `STRCMP`, which does not exist in
  Snowflake. It is a no-op here (port never connected), so it is intentionally not ported; do not
  reintroduce it.
- **`TO_DATE(TO_CHAR(SYSDATE),'DD/MM/YYYY')`** — always-NULL in the legacy engine and reproduced as
  NULL. On Snowflake this expression would raise `Can't parse ... as date with format 'DD/MM/YYYY'`
  rather than return NULL (unless `TRY_TO_DATE` is used); the models emit NULL directly, which is
  safe to deploy but should be flagged to the business as preserved legacy behavior.
- **Aggregator pass-through semantics** — `demo_target6` relies on last-row-per-group semantics,
  implemented with a window (`ROW_NUMBER() ... ORDER BY TX_ID DESC`) plus `SUM(TX_AMT) OVER
  (PARTITION BY ACCT_ID)`. This is portable Snowflake SQL, but the deterministic tie-break on
  `TX_ID` must be kept — Snowflake gives no implicit row order.
- **Sequence `SEQ_GEN` (ACCT_KEY)** — emulated deterministically as `ROW_NUMBER() + 280` (current
  value 281). A Snowflake `SEQUENCE` object would not be deterministic across reruns; keep the
  window-function emulation if reproducibility matters, and note the legacy `CYCLE=YES` property is
  irrelevant at these volumes.
- **Lookup "Use Last Value" policy** — lookups are implemented as joins against deduplicated
  lookup tables (last value per key). Verify the dedup ordering matches operational expectations
  before pointing at live Snowflake lookup tables where duplicate keys may occur.
- **`RTRIM`/`LTRIM`** — identical semantics in Snowflake; no change needed.
- **Flat-file date format** — `demo_source5` dates arrive as strings (`mm/dd/yyyy hh24:mi:ss`
  file attribute; `SELL_ED_DT` parsed with `DD/MM/YYYY`). On Snowflake, ingest via stage with an
  explicit `DATE_FORMAT`/`TIMESTAMP_FORMAT` file format rather than relying on implicit casts.
