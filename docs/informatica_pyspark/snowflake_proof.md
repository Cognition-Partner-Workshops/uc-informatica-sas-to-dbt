## What this proof does not cover

- Both sides’ tables are created from the same `TARGET_INSTANCE_SCHEMAS` registry, and the registry types come from mapping output rather than the XML. A type-domain error shared by both sides can therefore pass `MINUS`; only the local `parity_diff` run compares values against an independently generated baseline.
- Baseline tables are loaded from `baseline/informatica/*.csv`, generated by `tools/informatica_baseline.py` from the same seed CSVs consumed by the migrated run. This proves reproduction of legacy semantics on this seed data, not correctness on data the seed does not exercise.
- Warehouse types deviate from the XML target declarations: `demo_target1_*.CREATED_TIME`, `UPDATED_TIME`, `START_DATE`, and `END_DATE` are `DATE` although XML says `timestamp`; `demo_target3.PRODUCT_ID`, `PRODUCT_NO`, `STD_COST`, and `LIST_PRICE` are `VARCHAR` although XML says `number`; `demo_target6.TX_AMT` and `demo_target5.BAL_AMT` are `FLOAT` although XML says `number(p,s)` precision 38 scale 0, which would truncate decimal amounts. These follow the already-merged mapping output types; this milestone did not change them.
- The seven targets were verified, but each contains only 2–4 rows. Nothing here exercises volume, partitioning, or spill behavior. `MINUS` over a handful of rows is a weak test of joins or aggregations that could fail at scale.
- `__ROW_ORD` correctness is asserted by the loader’s ordering check, which uses the same loader path that materializes the column. An independent check would compare the loaded values directly against CSV bytes.
- Snowflake connector metadata probes emitted nonfatal cloud metadata warnings in this environment; they did not fail the run.
- The `ABORT()` failure path was not exercised against Snowflake. The seven-target success run does not prove partial-write behavior for a failing Snowflake mapping.
- The checksum is an order-independent aggregate and can theoretically collide; the bidirectional `MINUS` checks are stronger for the captured rows but still inherit the shared schema and seed-data limitations above.
